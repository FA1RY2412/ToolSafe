# Перевірювані сценарії

T01/T02 стосуються поточної ЛР1. T03–T12 є планом ЛР2, їх не виконано. Час реакції відлічувати від електричного OUT або зміни керованого параметра моделі, а не від початку руху людини. Результати зберігати з версією firmware, конфігурацією й фактичним середовищем.

| Тест / вимога | Вхід і дія | Критерій та доказ |
|---|---|---|
| T01 / FR-01 | Чиста Docker-збірка, запуск/перезапуск Wokwi | ready та послідовні tick мінімум 10 с; знімок UART. Перезапуск дає новий ready і uptime від нуля |
| T02 / FR-02 | Спостерігати PA5 мінімум 10 с | LED змінює стан, інтервал близько 1 с, повний цикл близько 2 с. Для точного часу в ЛР2 додати logic analyzer, не робити висновок із швидкості відео |
| T03 / FR-03 | guard→issue→guard, невідома команда, reset | Один запис на зміну; невідома команда не змінює режим; reset починає guard/calibrating |
| T04 / FR-04 | Simulate Motion, HIGH 5 с, LOW, другий фронт | Один approach на фронт за ≤100 мс, жодної охоронної тривоги від одного PIR |
| T05 / FR-05 | Стабільне світло, крок >15% ADC, повернення <10%, шум біля порогу | light_change за ≤200 мс; без повторів при утриманні; гістерезис працює; зберегти raw ADC і час |
| T06 / FR-06 | Стан 0/0/1 g, імпульс понад 0.8 g від фону; обертання понад 30 °/с | impact/body_motion за ≤100 мс; значення нижче порогу не створюють подію; перевірити насичення та всі осі |
| T07 / FR-07 | guard, PIR=0, удар; окремо зміна світла без удару | Обидві події окремо дають тривогу; PIR не потрібний; світлова тривога не називається доказом зламу |
| T08 / FR-08 | issue, світло й рух корпусу; потім guard і повтор | У видачі записи дозволеного доступу, без охоронної тривоги; після guard повертаються правила охорони |
| T09 / FR-09 | Серія різних подій, reset | Кожен запис має uptime_ms, режим, тип, значення, якість; після reset uptime від нуля, старий журнал існує лише на хості |
| T10 / FR-10 | Від'єднати MPU/NACK, окремо змоделювати timeout ADC | Статус fault, немає застарілого валідного виміру; PIR/інше джерело працює; повтор 1000 мс. Для ADC використати контрольоване введення помилки в тестовій ЛР2, не видавати стабільний рівень за timeout |
| T11 / FR-11 | Одночасно PIR, світло, удар; повторити з несправним MPU | Усі доступні типи подій присутні, PIR не приховує удар; перевірити строк реакції та період опитування 20 мс |
| T12 / FR-12 | 2 с спокою; рух під час калібрування; повторна команда в guard/issue | До валідного фону calibrating, неспокій не дає хибного normal; перекалібрування тільки у видачі |

Додатковий негативний сценарій: змоделювати доступ без зміни світла, удару чи PIR. Система може не зафіксувати його. Це обмеження спостереження, не успішна перевірка замка. Окремо перевірити зовнішню зміну освітлення без відкриття та випадковий рух корпусу: сенсори не визначають причину.

Пороги 15/10% ADC, 0.8/0.5 g, 30/20 °/с та строки реакції є стартовими припущеннями PRD. Вони потребують підбору, логів і вимірювань. У поточній прошивці немає цієї логіки.
